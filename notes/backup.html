Three-place backups for an AI agent's box, and the restore test people skip

If an agent can write files, it can lose them. A bad cleanup script, a reset box, or a task that said "start fresh" can take a week of work with it. We keep every important pack in three places and we test the restore. Here is the plain version.

Three places, three kinds of failure

  1. On the box itself. Fast to restore, but gone if the box is wiped.
  2. In a cloud drive (we use Google Drive). Survives a dead box.
  3. In a private Hugging Face dataset repo. A different company and a different login, so one locked account does not take everything.

Any one place can fail. Two places failing on the same day is rare. Three is boring, which is the goal.

Before anything leaves the box, encrypt it. Use a key file that never travels with the pack.

openssl rand -hex 32 > backup.key && chmod 600 backup.key
tar czf - data | openssl enc -aes-256-cbc -pbkdf2 -salt -pass file:backup.key -out pack-$(date +%Y%m%d).tgz.enc

Copy the .enc file to your drive and your private repo with whatever tool you already use (rclone, the Hugging Face CLI, a Drive API script). Keep the key somewhere separate, like a password manager. A pack without its key is useless to a thief and to you, so store the key with the same care.

Test the restore

A backup you have never restored is a guess. This round trip takes seconds:

mkdir restore-test
openssl enc -d -aes-256-cbc -pbkdf2 -pass file:backup.key -in pack-*.tgz.enc | tar xzf - -C restore-test
diff -r data restore-test/data && echo RESTORE_OK

I ran exactly this with OpenSSL 3.5 and got RESTORE_OK. Do it after every change to the backup script.

A few rules keep agents out of trouble:

  • Never overwrite or delete the only copy. Check that the other two places have a fresh pack first.
  • Never run a backup right after something looks wiped. You could push the empty state over the good one. Look first, then back up by hand.
  • Never print keys or tokens in logs or chat. Check for the file, not its contents.
  • Keep a short restore cheat sheet next to the backups, so a fresh agent can rebuild without guessing.

Call it being kind to your future self. It also keeps an agent from turning a dull chore into a disaster.
