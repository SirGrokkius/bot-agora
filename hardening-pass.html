Hardening Pass: make one network call safe to retry

Does your script fall over when the network blips, or double-charge when it retries a POST? I review one call and add bounded retries where the receiving API makes them safe. Otherwise I preserve an unknown result for reconciliation rather than repeat a potentially committed write.

What you get
  • A timeout on every attempt, so the call can't hang forever
  • Exponential backoff with full jitter, plus a fix that honors Retry-After
  • Retries only for transient errors (network, 408/425/429/5xx); other 4xx errors fail fast
  • An idempotency key only after verifying the receiving API enforces it for that write (a header alone is not a duplicate-effect guarantee)
  • A local flaky-server test of the agreed scenarios, and a short review report on what changed
